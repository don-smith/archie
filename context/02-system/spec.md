# 02-system — spec

## Status: Draft

Current system behavior. Unmarked content describes present supported behavior.

## Runtime composition

A target receives two npm artifacts — `@archie/runtime` and `@archie/conformance` — plus the APM-deployed context. The runtime exposes the Architecture Docs command; the conformance package is the only workspace that exposes `architecture-conformance`. The runtime carries the platform analyzer payload and the v2 dependency lock template, and ships the architecture-status schema and the complete Architecture Docs command implementation.

The deployed context is generated by `scripts/sync-context-skills.mjs` and contains exactly:

- eight skill trees: `archie`, `architecture-assessment`, `architecture-conformance-onboarding`, `architecture-contracts`, `architecture-docs`, `architecture-review`, `html-design`, `likec4-authoring`;
- two reference documents projected byte-for-byte: `docs/archie/managed-site-guide.md` and `docs/archie/deep-module-vocabulary.md`;
- the runtime dispatch script.

The projection check compares file counts and SHA-256 digests per file and fails on any difference. The repository-root `context/` tree is not part of any projection or package allowlist. Assessment ships without MyFlow lifecycle behavior, and HTML Design's checker runs without installed dependencies from the deployed skill.

## Analyzer and evidence contracts

The supported analyzer environment is exact: adapter `typescript-program-v1`, TypeScript `7.0.2`, Node 24, Darwin arm64, platform package `@typescript/typescript-darwin-arm64@7.0.2`. Any other platform or Node major fails before analysis; it is not an implied compatible configuration. TypeScript compiler objects stay inside the adapter; the core receives language-neutral requests and returns normalized observations, gaps, provenance, and completeness.

Known retained analyzer defects are recorded in the runtime analysis contracts (`knownDefects`) and visible in compatibility evidence and later reports:

- `export type { Named }` is classified as type-only, while `export { type Named }` is classified as runtime.
- A compiler-option diagnostic is repeated once per source file.

They are intentionally not repaired or hidden in this release. Python analysis, TypeScript LSP substitution, non-Darwin platforms, and a broader compatibility claim are deferred.

## Producer and consumer contracts

The producer records are frozen at their v1 shapes. `@archie/assessment` publishes `assessment-evidence/v1`: it reports model completeness, evidence availability, factual correction, recommendation triage, and authority; `ready` means those gates are complete, `unavailable` and `unknown` evidence stay visible and cannot be interpreted as approval, and recommendation outcomes remain developer-owned. `@archie/conformance` keeps the parity-frozen `conformance-report/v1` and `onboarding-state/v1` artifacts; its public consumer envelopes are `conformance-report-contract/v1` and `conformance-state-contract/v1`, which add report identity, result-code meanings, evidence digests, freshness inputs, and state versions without changing the producer artifact bytes.

Conformance result codes are fixed: `0` pass, `1` blocking violation, `2` incomplete evidence, and `3` invalid input. Freshness is `fresh`, `stale`, `unavailable`, or `unknown`. A downstream consumer must preserve these meanings and must not convert missing or uncertain evidence into a pass. Package roots export readers only; validators, engines, storage, and renderers remain private. The handoff defines no adapters, status rendering, managed-site warnings, or documentation consumption.

Producer/consumer evidence stays in target-owned commands: onboarding observes the import graph, contracts check it deterministically, and Architecture Docs validates its own presentation against the accepted handoff. Archie does not convert these results into a universal architecture verdict.

## Rehydration and recovery

A fresh branch or worktree carries the pin but not the installed tree; the first skill run hydrates from the local npm cache and, when the cache is cold, prints the one command to run. Recovery replays the install journal with the exact bytes of every touched path.
