# Archie ontology

Canonical Archie-maintainer terminology. This file owns the terms and their stable meanings; the deployed reference sources explain the same terms for their audiences.

## Product terms

| Term | Meaning |
|---|---|
| Archie | The architecture agent product: one package of agent skills plus a pinned project-local runtime, coordinated by the `archie` skill. |
| Capability | A maintained skill or deterministic operation with a named responsibility, contract, and authority stop. The seven registered capabilities are `assessment`, `architecture-docs`, `likec4-authoring`, `conformance-onboarding`, `architecture-contracts`, `architecture-review`, and `html-design`. |
| Authority stop | The decision point where a human (developer or maintainer) retains control, such as approving claims, triaging findings, or choosing architecture intent. |
| Proposal | The decision packet Archie presents before a durable or material change; the developer decides whether it applies. |
| Repository evidence | Inspectable repository facts: source, configuration, documentation, history, and stated conventions. |
| Host adapter | Host-specific wiring that exposes the portable Archie core and supplies host UI, configuration, and approval behavior; it never forks capability logic. |
| Architecture asset | A repository-owned model, diagram, glossary, documentation page, decision record, or generated output that describes architecture. |
| Onboarding mode | The operating mode that inventories repository evidence, conventions, architecture assets, ownership, unknowns, approval requirements, and the safest next action. |
| Operational mode | The operating mode that handles a specific architecture question or change by selecting the narrowest capability that owns the work. |
| Result meaning | What a capability's output certifies, which routing preserves: an assessment result is not a pass, findings are not an architecture pass, and observed code never becomes approved intent by itself. |
| VRS / intent layer | The `context/` tree: the sole current source of settled Archie-maintainer intent. "VRS" follows the LiveStore precedent the tree is modeled on. |
| Maintainer-only | A property of the VRS tree: it is a source-only module that packages, APM projections, and installed targets exclude. |

## Delivery terms

| Term | Meaning |
|---|---|
| Product version | The lockstep SemVer identity (`v<version>` tag) shared by every workspace, lock, projection, and fixture. Independent of the release-record schema version. |
| Release-record schema version | The closed record format version, today `3`; a record's `schemaVersion: 3` is not the product version. |
| Release record | The finalized `release-record-v3.json` pinning product version, source commit, artifact identities and hashes, npm lock, APM evidence, and analyzer compatibility. |
| Authorization | The v3 release-record field whose required literal is `authorization: {kind: 'none', claim: 'locally-reviewed-private-trial'}`. It is a legacy protocol wire value, not review evidence, and does not authorize a release. |
| APM | The Agent Package Manager that deploys the eight Archie skills into a target from an immutable ref, plus the native manifest and lock evidence. |
| Projection | A generated byte copy of a canonical source; only the eight skill trees, the two reference documents, and the runtime dispatch script are projected. |
| Producer artifact | A frozen released record such as `assessment-evidence/v1`, `conformance-report/v1`, or `onboarding-state/v1`; producer bytes never change for consumers. |
| Consumer envelope | A public contract wrapper (for example `conformance-report-contract/v1`) that adds identity, result-code meanings, and freshness inputs without changing producer artifact bytes. |
| Companion guide | A step-by-step runbook kept under its owning node (for example `03-delivery/guides/`), not an intent authority. |
| Bundle | The finalization input directory (`bundle.json`, `npm/`, `apm/`) that a maintainer reviews locally before finalization. |
| Delta | A `.delta/DELTA-NNN-slug.md` record of a specific, observed divergence between intent and reality, with an owner and closure check. |
| Decision record | An accepted `.decisions/NNNN-slug.md` record with dated evidence and real rejected alternatives. |
| Structure check | The dependency-free `scripts/check-intent-tree.mjs` validator; it certifies structure, never semantic truth. |
